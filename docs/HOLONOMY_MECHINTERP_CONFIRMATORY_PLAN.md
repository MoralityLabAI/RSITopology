# Holonomy mechinterp falsification: Qwen execution plan

## Question

Can a gauge-invariant measurement of representation transport organize
mechanistic-interpretability data into reusable context-by-checkpoint patches,
and does loop holonomy predict when two locally plausible transports produce
different causal effects?

The operative claim is deliberately narrower than "transformer capabilities
are topological":

> After controlling for edit norm, site, family, Jacobian visibility, and
> pairwise lineage, directional loop displacement may predict path-dependent
> causal disagreement for signed interventions.

The experiment is useful if the answer is yes or no. A yes gives the VPD edit
program an identity stratum and a risk feature. A no localizes the failure to
one of four registered boundaries: no recoverable family object, no
lineage-connected graph, no holonomy above estimation noise, or geometry with
no held-out causal value.

## What is already established

The CPU-synthetic causal calibration in
`holonomy_causal_transfer_falsification_v0_1` passed all ten gates. On 3,456
rows, adding the frozen holonomy features reduced grouped held-out SSE by
0.8900 (grouped-bootstrap 90% interval 0.8491--0.9232), while a seeded
permutation achieved 0.0525. The exact two-path identity held to
`9.992e-16`; the registered Lipschitz bound had no violations; conservative
authorization covered 91.29% of rows with zero false authorizations.

That establishes an instrument and a planted failure mode, not transformer
evidence. The recovered Qwen3-1.7B results set the real boundary: the old
layer-local object supported no modules, prompt identity explained more than
95% of retention variance, and a single global soft atlas had no stable
measurement-scale window. The next graph therefore uses **context × genuine
model state**, not adjacent depth and not runtime precision.

## Why 0.8B is enough for development

The Qwen3.5-0.8B base and three existing LoRA adapter states give a real
four-state checkpoint axis. Four late full-attention residual blocks provide a
common 1,024-dimensional ambient coordinate. This is enough to test:

1. whether the between-class object survives its matched-label null;
2. whether the lineage-thresholded graph has cycles;
3. whether measured loop closure survives prompt resampling; and
4. whether prereveal path displacement has causal value on untouched prompts.

The adapters came from an eight-row smoke run, so this phase cannot adjudicate
whether VPD training is better than shuffled or naive training. It is an
architecture, cost, and mechanism pilot. Qwen3-1.7B remains the confirmatory
model after new construction-only checkpoints are provenance-stamped.

## Registered stages

### R0: synthetic causal instrument

Status: passed. This stage validates polarity, path conventions, controls,
gauge replay, orientation denial, and analysis code.

### R1: natural geometry census

For each model, residual-block site, behavior family, context shard, model
state, and rank 1--8:

- form the cross-fitted between-class scatter object from construction and
  geometry-validation halves;
- require the matched random-label negative control;
- build the lineage graph at frozen floors 0.80, 0.85, 0.90, and 0.95, with
  0.90 primary;
- compute connected components and `beta_1 = |E| - |V| + c(G)`;
- admit only within-component elementary context-by-checkpoint loops;
- compare validation holonomy against prompt-resample estimation noise; and
- test whether within-family partial transports are more stable than
  equal-rank cross-family transports.

The covariance/Gram object is reported, but no decision may consume it.

The result vocabulary is total:

| Boundary | Result |
|---|---|
| label control fails | `negative_control_not_passed` |
| supported rank is zero | `no_supported_identity_rank` |
| `beta_1 = 0` | `holonomy_unavailable` |
| loops do not clear noise | `lineage_only_no_noise_valid_holonomy` |
| family contrast fails | geometry only; no behavior-grouping claim |
| all gates pass | eligible prereveal loop universe |

No rank, floor, axis, or prompt change is allowed after seeing which boundary
was hit.

### R2: held-out causal path transfer

Before any outer prompt is read, the geometry run seals:

- the loop universe and receipt hashes;
- the two edge orders from one root to one target;
- exposed, Haar, and minimally exposed root directions;
- the common target basis and both target ambient edits;
- residual-relative norm fractions 0.01, 0.025, and 0.05;
- baseline and augmented feature columns;
- grouped folds; and
- the candidate table hash.

The two edits differ only in transport path. Both are applied at the same
model state, site, token, sign, and norm. Six prompts from the target family
and context shard are then assigned from the independently generated
`causal_outer` universe.

The primary outcome is the absolute disagreement between the two edits'
changes in teacher-forced expected-answer negative log likelihood. Next-token
Jensen--Shannon distance and final-residual response disagreement are
secondary, lower-variance mechanism endpoints.

The primary test compares grouped out-of-fold prediction using nuisance and
local features against the same model plus directional path displacement,
canonical angle, identity loss, and noise-exceedance margin. Support requires:

- at least 10% held-out SSE reduction;
- a grouped-bootstrap one-sided 95% lower bound above zero; and
- an exposed-versus-minimally-exposed within-loop dose response above zero.

Flat-within-noise loops, Haar directions, permuted holonomy features, and
orientation reversals are mandatory controls. A real-model authorization
curve is empirical; the exact synthetic Lipschitz bound is not silently
promoted into a transformer guarantee.

### R3: VPD edit stratification

This opens only after the Qwen3-1.7B confirmation passes R2. VPD-selected and
matched-random weight edits are compared inside the same registered identity
and holonomy-risk strata. If identity-clean VPD edits still fail to beat
matched random, the VPD null strengthens. The atlas is not revised on the VPD
outcomes.

## Demonstration versus confirmation

| Property | Qwen3.5-0.8B | Qwen3-1.7B |
|---|---|---|
| Purpose | development and real-geometry pilot | confirmation |
| States | base + 3 existing adapters | base + >=2 new construction-only checkpoints |
| Sites | residual outputs at L11/L15/L19/L23 | residual outputs at L16/L19/L22/L25/L27 |
| Positive claim ceiling | provisional; not a VPD comparison | protocol-scoped real-model evidence |
| Natural collapse | publishable boundary | confirmatory negative result |

Simple geometry is acceptable. A rank-one flat bundle can demonstrate a
stable grouping, but it cannot demonstrate nontrivial holonomy. Geometry that
appears under construction and collapses under held-out resampling is reported
as estimator support below the instrument floor. The visualization may render
both cases, but its globe and swirl remain presentational; only receipts drive
claims.

## Execution and resource boundary

Model-bearing runs require a validated hard-cap wrapper covering RAM/commit,
CPU, I/O, timeout, zero swap, and GPU allowance, with chunked capture and
cleanup receipts. The current 4 GB laptop GPU and low free system RAM are not
an approved path. The implementation and prompt manifests can be finalized
locally; the capture should run through the already demonstrated capped Silico
or equivalent job environment. Abort and `holonomy_unavailable` are valid
outcomes.

## Deliverables

1. A byte-disjoint 576-row `causal_outer` prompt manifest.
2. Qwen3.5 block-output/state capture adapter with write-once chunks.
3. Stage-1 geometry release: node objects, edge and loop receipts, noise
   calibration, bifiltration, certificates, and globe files.
4. Hashed prereveal candidate table with ambient path edits.
5. Stage-2 paired intervention records and grouped inference report.
6. A Qwen3-1.7B confirmatory replay using the frozen implementation.

The scientific contribution is not the picture of a curved globe. It is the
separation of three questions that ordinary feature browsers conflate:
whether a feature subspace exists, whether its coordinates transport
consistently, and whether failures of that consistency predict causal control
risk.
