# ASMP bounded round-robin: consolidated experiment and resource report

## Executive result

Seven problem-specific proposers produced one bounded experiment each, and
each proposal received exactly one review from its neighbor in the registered
ring. No experiment was executed.

The review distribution is informative:

- `run_pilot`: 1/7 (`ASMP-2`), with the result restricted to a forced exact
  construction and implementation checker;
- `revise_before_pilot`: 6/7; and
- `do_not_run`: 0/7.

This is a useful skeptical outcome. The proposals are not seven endorsements:
the reviews found four load-bearing estimand or quantifier defects, two
underspecified finite universes, and one scope mismatch between conditional
prediction and causal identifiability.

## What each experiment would actually establish

### ASMP-1: context-conditioned prediction, not identification

The experiment asks whether prereveal context features predict coordinated
intervention responses that a global interaction model misses. A pass could
produce an advisory `ContextInteractionPredictionReceipt`. It would not show a
unique mechanism modulo symmetry and would not authorize a VPD edit.

### ASMP-2: one exact local-to-global counterexample

The crossed term analytically forces the registered `O(t^2)` local ambiguity
and nonzero global ambiguity. The pilot is worth keeping as a tiny theorem
checker and certificate example, not as empirical support for a general
continuation law. The optional active-design sweep is the first part whose
outcome is not planted.

### ASMP-3: a bounded robust-verification game

After repair, the experiment can measure separate uniform soundness and
completeness against a finite obfuscator/noise class. It cannot define the
general weak-verifier complexity frontier or infer human/superhuman semantic
verification from a synthetic oracle.

### ASMP-4: architecture-certified two-port feasibility

With one universal controller, exact synthesis can expose read/write
compensation or rectangularity inside a frozen finite grammar. It cannot prove
continuous-system optimality outside that grammar. This proposal had the
clearest reviewer-discovered quantifier bug and therefore the clearest value
from the round-robin process.

### ASMP-5: minimal bounded verifier-drift counterexample

A shared candidate graph can isolate which checker accepts each otherwise
identical transition. Exhaustive search may then produce a genuine minimum
finite counterexample or a finite classification. It remains silent about
unbounded reflective progress. The optional Qwen arm measures only recursive
gain through proposal quality under a frozen selector.

### ASMP-6: finite-horizon covert-capacity bounds

The safe artifact is aggregate converse/phase-boundary evidence, not learned
codebooks. Keyed and unkeyed results must remain separate. A finite grid cannot
be called zero or positive asymptotic rate without a checked composition or
subadditivity argument.

### ASMP-7: one worked telemetry access class

The proposed LP can validate uniform composite testing and trace-equivalence
impossibility only after its transformation and observation spaces are proved
finite. It would be a worked access-class example, not evidence that real
telemetry is complete or that signatures imply semantic coverage.

## Recommended focused execution order

### Tranche A: exact CPU instruments

1. Run the ASMP-2 analytic checker after pinning Fisher whitening.
2. Amend ASMP-4 to use one universal controller, then run its smallest exact
   horizon.
3. Amend ASMP-5 to use one paired candidate-edge graph, then run its smallest
   exact universe.

Nominal compute for these three pilots together is approximately **6–17 minutes
of serial wall time**, no GPU, and <=2 GB peak RAM. Registration and review
work—not compute—will dominate.

### Tranche B: one robust synthetic oversight pilot

Repair ASMP-3's FP/FN estimand and finite conditional-noise table, then run the
small census. This adds 3–8 minutes and <=1 GB RAM. Run it only if HRMmmm will
consume the resulting abstain/escalate policy.

### Tranche C: first real-model contact

Repair ASMP-1 and run the existing-data analysis first. Only if the instrument
and capacity controls pass should the four-site confirmation spend **1–2
GPU-hours**. Do not open the six-site/1.7B scale-up from a merely suggestive
pilot.

### Defer

- ASMP-6 full and learned runs: highest resource and dual-use burden; definitions
  must be repaired before any solver or model work.
- ASMP-7 scale-up: its quoted complexity is not meaningful until the finite
  orbit and sufficient-statistic reduction are counted and proved.
- All optional GPU scale-ups: running every proposed option would cost roughly
  **21–40 GPU-hours** and would be the unfocused token/compute feast this
  workshop was designed to avoid.

## Focused budget recommendation

The useful near-term package is Tranches A and B plus ASMP-1's analysis-only
preflight:

- expected serial compute wall time: **about 19–45 minutes** after protocols
  are repaired;
- peak RAM: **<=2 GB** for the CPU pilots;
- disk: **well under 1 GB**;
- GPU: **0 hours initially**; and
- contingent GPU authorization: **1–2 hours at <=3.4 GB VRAM** for ASMP-1 only.

This preserves ULTRA's collaborative value—independent formalization and one
skeptical pass—while forcing downstream compute to earn its way through cheap
gates.

## Process boundary

This workshop generated research proposals and adversarial reviews. It did not
preregister, execute, validate, or resolve any ASMP. Every `revise_before_pilot`
item requires a versioned amendment before results are visible. ASMP-2's pilot
may proceed only with its forced-construction label and should not be cited as
evidence for a general shift-certification theorem.
