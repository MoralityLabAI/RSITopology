# ASMP-4 registry-reopening negative-feasibility result v0.37

## Disposition

The proposed `128 x 8,192` registry-indexed support-fibration census is
**NO-GO**.  Its proposed domain is not derived exhaustively from the canonical
ASMP-4 source, so running it cannot establish a source-faithful capacity region
or a registry-independence theorem.

This is a proof-to-the-negative about that proposed successor's feasibility.
It preserves the v0.36 stop, does not select a normative registry, and does not
resolve ASMP-4.

## Proposed successor reviewed

The rejected design treated seven items named by v0.36 as Boolean coordinates
`sigma in {0,1}^7`, then proposed to enumerate 8,192 small causal codes for
each of 128 completions.  It would build read/write transcript-support DFAs,
pair their spectral rates, and call the intersection of completion regions a
robust core.

The arithmetic product

```text
128 x 8,192 = 1,048,576
```

is correct as a count of proposed code-completion evaluations.  The factors
are not justified as an exhaustive source-derived universe.

## Negative-feasibility proof

Let `S` be the canonical ASMP-4 text and let `Comp(S)` be the class of formal
completions consistent with its explicit clauses.  A source-exhaustive Boolean
catalog would require a map

```text
B : {0,1}^7 -> Comp(S)
```

whose image is all of `Comp(S)`, with every coordinate backed by a canonical
clause that supplies an exhaustive two-element codomain.

The canonical source does not supply such coordinates:

1. admitted sensor grammars and actuator-dictionary domains are registered
   families, not binary choices;
2. normal hyperbolicity and local controllability are required predicates on a
   declared class, not optional on/off selector values;
3. public-belief and reset/safe-closing semantics are later conditional-proof
   hypotheses, not canonical binary selectors; and
4. probability/disturbance order is source-relevant, but it is inert in the
   proposed deterministic code census.

Therefore no exhaustive `B` follows from `S`.  The 128 rows would be
investigator-authored tagged models.  Exhausting them could neither select a
normative completion nor prove equivalence over all source-compatible
completions.  It consequently satisfies none of the v0.36 reopening
conditions: no formal normative registry, no attributable semantic
adjudication, no sealed-premise error, and no registry-independent equivalence
theorem.

## Additional mathematical defects

- The proposed `8,192` codes need an explicit typed bijection from 13-bit
  strings to sensor, controller-memory, and actuator maps.  Without it the
  count is an assertion, not a registry certificate.
- `intersection_sigma R_sigma` expresses
  `for all sigma, there exists C_sigma`.  A single robust code instead requires
  `there exists C, for all sigma`.  These quantifiers must be computed and
  reported separately.
- Marginal read and write transcript radii give coordinate rates for one code.
  They do not alone prove a joint tradeoff region.  Convexification or time
  sharing needs a reset/concatenation theorem.
- Exact asymptotic spectral rates require reachable and co-reachable
  multiplicity automata plus characteristic-polynomial/root certificates.
  Agreement of finite counts through horizon eight is only a consistency
  check.
- The proposed work materially overlaps the v0.6/v0.9 finite registries,
  v0.18--v0.21 support/spectral packages, v0.24 weighted regions, and v0.31
  finite-quotient geometry without addressing the v0.36 normative root.

## Kill gates for any later reopening attempt

Any future source-fibration assignment must stop unless all of the following
hold:

1. Every selector has a direct canonical clause and an exhaustive finite
   codomain.
2. Every selector is non-inert on the registered fixture.
3. The typed code grammar independently proves its exact code count.
4. Infinite-horizon statements follow from graph/algebraic certificates, not a
   finite horizon prefix.
5. Spectral claims carry exact algebraic root certificates.
6. `for all completion, exists code` and `exists one code, for all completion`
   are kept separate.
7. The package makes no normative, source-exhaustive, or ASMP-4-resolution
   claim unless an actual v0.36 reopening condition is independently met.

## Claim boundary

The result rules out only the proposed Boolean 128-completion experiment as a
source-faithful reopening.  It does not prove that every formal ASMP-4
completion lacks a capacity theorem.  Conditional v0.33--v0.35 theorems and the
v0.6/v0.8 material forks remain intact, and ASMP-4 remains unresolved.
