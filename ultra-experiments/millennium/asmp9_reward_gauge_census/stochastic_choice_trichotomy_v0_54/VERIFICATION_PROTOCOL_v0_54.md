# ASMP-9 v0.54 stochastic-choice verification protocol

## Status

This protocol freezes an exact finite verification of a classical nested
representation trichotomy. Development outputs are burned. Only the separately
committed verifier, prospective registration, and write-once result are
claim-eligible.

## Frozen universe

Use three labelled alternatives:

```text
X = {a,b,c}.
```

Observe all three binary menus and the ternary menu. Census every strictly
positive kernel whose menu probabilities are integer multiples of `1/6`.
There are:

```text
5^3 * C(5,2) = 1,250
```

such kernels.

## Frozen classifications

### `scalar_luce`

All probabilities are generated by one positive ratio scale. Normalize the
scale by the full-menu probabilities and check every pair exactly.

### `random_utility_non_luce`

The Luce identities fail, but every Block-Marschak polynomial is nonnegative
and an exact nonnegative distribution over the six strict rankings reproduces
every observed probability.

### `no_random_utility_representation`

At least one Block-Marschak polynomial is negative and no nonnegative
distribution over the six strict rankings reproduces the kernel.

## Independent verification

The verifier must not import `stochastic_choice.py`. It must:

1. independently enumerate the 1,250 kernels;
2. compute the Luce equalities by exact rational cross-products;
3. compute every Block-Marschak polynomial by exact inclusion-exclusion;
4. solve the ranking-mixture equations by an independent exact row reduction;
5. require the Block-Marschak and ranking-simplex decisions to agree on every
   kernel; and
6. reproduce every event from every admitted ranking mixture.

## Frozen targets


These counts are verification targets for the registered denominator-six

## Canonical witnesses

### Scalar

Luce weights proportional to `(1,2,3)`:

```text
p(. | ab)  = (1/3,2/3)
p(. | ac)  = (1/4,3/4)
p(. | bc)  = (2/5,3/5)
p(. | abc) = (1/6,1/3,1/2).
```

### Random utility, non-Luce

Put mass `1/3` on each of:

```text
a>b>c, b>c>a, c>a>b.
```

The induced kernel must be strictly positive and random-utility
rationalizable but must fail the Luce pair/full-menu identities.

### No random utility

Use fair binary menus and ternary probabilities `(3/4,1/8,1/8)`. The exact
certificate is:

```text
q(a,{a,b}) = 1/2 - 3/4 = -1/4.
```

## Access witness

The no-object witness and the uniform Luce kernel must agree byte-for-byte on
their three binary-menu projections. Their ternary responses differ. Thus
binary access cannot decide the endpoint classes in the registered universe.

## Gates

### H0: source integrity

Every registered source hash must match.

### T0: tests

All registered scientific and verifier tests must pass.

### C0: census completeness

Exactly 1,250 kernels must execute with the frozen class counts.

### E0: equivalent rationalizability decisions

Block-Marschak nonnegativity and exact ranking-mixture feasibility must agree
on all 1,250 kernels.

### S0: scalar tier

The scalar witness and the unique scalar census cell must carry valid Luce
weights and valid random-utility mixtures.

### R0: middle tier

The planted cyclic ranking mixture must be classified
`random_utility_non_luce`; the middle census tier must be nonempty.

### N0: no-object tier

The planted regularity violation must be classified
`no_random_utility_representation` with the exact `-1/4` certificate.

### A0: access insufficiency

The scalar and no-object access witnesses must have identical binary
projections and different endpoint statuses.

### RESOURCE

Verification must finish within 60 seconds and 256 MiB resident memory using
one worker.

## Stop rule

Every gate must pass exactly. A missing kernel, equality mismatch,
classification disagreement, source mismatch, certificate failure, or
resource-cap equality is failure. There is no discretionary override.

The verification result is write-once. Repairs must be additive and separately
registered.

## Claim boundary

Passing verifies an exact finite instrument built from classical
Luce/Falmagne/McFadden-Richter representation results. It does not establish
novelty, finite-sample performance, general incomplete-menu identification,
human or model rationality, moral value, strategic robustness, physical
preference-channel validity, or ASMP-9 resolution.
