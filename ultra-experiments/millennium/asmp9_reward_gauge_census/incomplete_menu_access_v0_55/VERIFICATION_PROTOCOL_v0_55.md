# ASMP-9 v0.55 incomplete-menu access verification protocol

## Status

This protocol freezes an exact finite access-theorem check. Development
outputs are burned. Only the separately committed independent verifier,
prospective registration, and write-once result are claim-eligible.

Existential stochastic rationalizability on arbitrary observed choice
problems is classical ARSP. The claim-eligible target is the distinction
between existence of one rationalizing completion and identification of the
full-kernel object tier.

## Frozen universe

Use:

```text
X = {a,b,c}

```

and every one of the 15 nonempty observed-menu domains `D subseteq M`.

Project all 1,250 positive denominator-six full kernels from v0.54 into each
domain, deduplicating projections within a domain.

## Independent algorithms

The verifier must not import `incomplete_menu.py`.

### Scalar compatibility

Propagate exact probability ratios over the observed comparison graph and
check every observed normalization. Inconsistent repeated ratios or cycle
products reject a Luce completion.

### RUM compatibility

Construct the observed deterministic-choice matrix over all six strict
rankings. Enumerate every exact basic solution of:

```text
A_D lambda = p_D,
lambda >= 0,
sum lambda = 1.
```

No floating-point LP decision is allowed.

### Non-Luce RUM completion

For every scalar-compatible proper-domain dataset, independently enumerate the
exact basic RUM completions and require at least one full completion to fail
the Luce identities.

### Non-RUM completion

For every proper-domain dataset:

- if `abc` is missing, choose a completed ternary probability larger than its
  corresponding pair probability; or
- if `abc` is observed, complete a missing pair below the full-menu
  probability.

Require a strict regularity violation and a negative full-domain
Block-Marschak polynomial.

## Gates

### H0: source integrity

Every registered source hash must match.

### T0: tests

All registered scientific and verifier tests must pass.

### D0: domain-lattice completeness

All 15 nonempty domains, 14 proper domains, and all 1,125 distinct proper
projections must execute. The canonical domain-summary hash must match.

### E0: existential compatibility

Exact scalar and RUM feasibility must be evaluated for every projection with
no normalization or solver failures.

### N0: non-RUM completion

Every proper-domain projection must admit the registered positive
regularity-violating completion.

### R0: non-Luce RUM completion

Every scalar-compatible proper-domain projection must admit an exact RUM
completion outside Luce. Every RUM-compatible but scalar-incompatible
projection must carry a RUM-but-non-Luce witness.

### TIER0: compatibility-set trichotomy

The exact proper-domain counts must be `{L,R,N}=128`, `{R,N}=422`, and
`{N}=575`.

### FULL0: complete-domain control

The singleton tier counts must be `{L}=1`, `{R}=230`, `{N}=1019`.

### RESOURCE

Verification must finish within 60 seconds and 256 MiB resident memory using
one worker.

## Stop rule

Every gate must pass exactly. Missing domains, count or hash mismatches,
nonexact decisions, construction failure, source mismatch, or resource-cap
equality is failure. There is no discretionary override.

The verification result is write-once. Repairs must be additive and separately
registered.

## Claim boundary

Passing verifies an elementary finite completion-ambiguity theorem layered on
classical Luce and ARSP tests. It does not establish representation-theorem
novelty, finite-sample or general-domain identification, endogenous-menu,
human/model, moral-value, strategic, dynamic, physical-channel, or full
ASMP-9 claims.
